# OSAC GitOps — Install Guide (RHOAI 3.6)

Deploys the OSAC MaaS platform on a hub and its spokes using the two-plane
ACM + GitOps design pattern.

| Site | Cluster | ACM ManagedCluster | Argo destination | Models |
|---|---|---|---|---|
| `site-a` (hub) | `hub` | `local-cluster` | `in-cluster` | `facebook-opt-125m`, `smollm2-135m-instruct` (CPU) |
| `site-b` (spoke) | `site-b-cluster` | `site-b` | `site-b` | same (CPU) |

- **Platform plane** (`hub/platform/`, policies 00–20): Argo applies ACM policies to the hub; ACM delivers them to every selected site.
- **Intent plane** (models, grid-models, governance): Argo pushes straight to each site.
- **Infrastructure** (policies 15–17): ODF, ACM, and Submariner as ACM policies for complete cluster management.

## 2. Bootstrap the Hub

```bash
oc config use-context "$HUB_CTX"
./scripts/bootstrap.sh --seed-pull-secret --yes
```

**What it does (12 steps):**
1. Installs the OpenShift GitOps operator, waits for CRDs and the ArgoCD instance
2. Creates `osac-platform` namespace
3. Configures Argo CD RBAC (cluster-admin for the controller, ACM policy RBAC)
4. Patches Argo controller memory (4Gi limit, 2Gi request)
5. Applies AppProjects (`platform-policies`, `scope-global`, `scope-tenant-novatech`)
6. Installs ACM operator (`release-2.17`) and waits for MultiClusterHub CRD
7. Creates MultiClusterHub (retries until the operator webhook is ready)
8. Creates ACM plumbing (ManagedClusterSetBinding, GitOpsCluster, Placement)
9. Creates Git repository secret (token from `gh auth token`)
10. Deploys `osac-layers` ApplicationSet (directory source filtered to `*.yaml`)
11. Creates hub-only Placement, pre-creates `maas-db` namespace, hub-templating RBAC
12. Seeds Quay pull secret (when `--seed-pull-secret`)

Then waits for all hub Applications to sync.

**Expected result:** Hub and platform-sites Applications show `Synced`. The ACM platform policies begin propagating. Site-a intent-plane apps (models, grid-models, governance) will remain `OutOfSync` until RHOAI operator CRDs appear — this is expected and resolves as policies install the operators.

### Grid PKI (automated)

Policy 20 (`osac-grid-pki`) automatically bootstraps all grid mesh PKI secrets on the hub using cert-manager and ESO — no manual `openssl` or `oc create secret` commands are needed:

| Secret | Generated by | Purpose |
|---|---|---|
| `grid-ca` | cert-manager (self-signed CA) | Grid mesh root of trust |
| `grid-site-identity` | cert-manager (signed by grid-ca) | Hub mTLS identity with SPIFFE URI |
| `grid-enrollment-tls` | cert-manager (signed by grid-ca) | Enrollment service HTTPS cert |
| `grid-swim-key` | ESO Password generator | SWIM protocol symmetric key |
| `grid-reserved-seeds` | Policy 20 (empty Secret) | Enrollment reserved seeds |

These secrets are created automatically once cert-manager and ESO operators are ready (installed by Policy 01). The enrollment service, gateways, and mirror policies all consume them without manual intervention.

**Spoke identities** are provisioned automatically by the enrollment protocol — when a spoke joins and receives its SiteInvite, the enrollment service issues its identity certificate. No manual cert generation is needed for spokes.

**Remaining manual secrets:**

| Secret | Why manual |
|---|---|
| `submariner-aws-creds` | Cloud credentials — must come from the user |
| `rhoai-quay-pull-secret` | Registry auth — `bootstrap.sh --seed-pull-secret` handles this |
| Cross-site model API keys | Requires running MaaS API to mint (see Section 5) |

## 3. Add a Spoke

### Option A: Using the import script (requires `clusteradm`)

```bash
./scripts/import-managed-cluster.sh \
  --hub-context "$HUB_CTX" \
  --spoke-context "$SPOKE_CTX" \
  --cluster-name site-b \
  --yes
```

After the script completes, add the cluster to the `global` ManagedClusterSet:

```bash
oc --context "$HUB_CTX" label managedcluster site-b \
  cluster.open-cluster-management.io/clusterset=global --overwrite
```

### Option B: Manual import (no `clusteradm`)

```bash
# 1. Create ManagedCluster on hub
oc --context "$HUB_CTX" apply -f - <<'YAML'
apiVersion: cluster.open-cluster-management.io/v1
kind: ManagedCluster
metadata:
  name: site-b
spec:
  hubAcceptsClient: true
  leaseDurationSeconds: 60
YAML

# 2. Wait for the import secret
until oc --context "$HUB_CTX" -n site-b get secret site-b-import >/dev/null 2>&1; do sleep 5; done

# 3. Extract and apply CRDs on spoke
oc --context "$HUB_CTX" -n site-b get secret site-b-import \
  -o jsonpath='{.data.crds\.yaml}' | base64 -d | oc --context "$SPOKE_CTX" apply -f -

# 4. Apply import manifests on spoke (installs klusterlet)
oc --context "$HUB_CTX" -n site-b get secret site-b-import \
  -o jsonpath='{.data.import\.yaml}' | base64 -d | oc --context "$SPOKE_CTX" apply -f -

# 5. Wait for the cluster to join
oc --context "$HUB_CTX" wait --for=condition=ManagedClusterJoined \
  managedcluster/site-b --timeout=10m

# 6. Add to the global ManagedClusterSet
oc --context "$HUB_CTX" label managedcluster site-b \
  cluster.open-cluster-management.io/clusterset=global --overwrite

# 7. Enable application-manager addon
oc --context "$HUB_CTX" apply -f - <<'YAML'
apiVersion: addon.open-cluster-management.io/v1alpha1
kind: ManagedClusterAddOn
metadata:
  name: application-manager
  namespace: site-b
spec:
  installNamespace: open-cluster-management-agent-addon
YAML

# 8. Wait for ArgoCD cluster secret
until oc --context "$HUB_CTX" -n openshift-gitops get secret \
  site-b-application-manager-cluster-secret >/dev/null 2>&1; do sleep 10; done
```

**What it does:**
1. Registers the spoke as a ManagedCluster with auto-accept
2. Extracts the klusterlet CRDs and import manifests from the hub-generated secret
3. Installs the klusterlet agent on the spoke
4. Waits for `ManagedClusterJoined` condition
5. Adds the cluster to the `global` ManagedClusterSet (required for Placement/GitOpsCluster)
6. Enables the `application-manager` addon
7. Waits for the Argo CD cluster secret (`<name>-application-manager-cluster-secret`)

Once the cluster secret appears, the `osac-layers` ApplicationSet generates the
spoke's Applications and policies begin enforcing.

Repeat for each additional spoke (replace `site-b` with the new cluster name).

## 4. Verify

### 4.1 Check policy compliance

```bash
oc -n osac-platform get policies
```

All policies should eventually show `Compliant`. Policies enforcing operator
installs may take 5–10 minutes to converge. If a policy stays `NonCompliant`:

```bash
oc -n osac-platform describe policy <policy-name>
```

### 4.2 Check Argo CD Applications

```bash
oc -n openshift-gitops get applications.argoproj.io
```

> **Note:** Use the full CRD name `applications.argoproj.io` — the short form
> `oc get applications` may return empty if another API group shadows it.

All 10 Applications should show `Synced` / `Healthy`. Site-a intent-plane apps
(models, grid-models, external-models, governance) may remain `OutOfSync` until
RHOAI and related operators finish installing and register their CRDs.

### 4.3 Run smoke tests

```bash
export HUB_DOMAIN=$(oc --context "$HUB_CTX" get ingresses.config.openshift.io cluster -o jsonpath='{.spec.domain}')
./scripts/smoke-test.sh --domain "$HUB_DOMAIN" --password "$KC_PASS"
```

For a spoke:

```bash
export SPOKE_DOMAIN=$(oc --context "$SPOKE_CTX" get ingresses.config.openshift.io cluster -o jsonpath='{.spec.domain}')
./scripts/smoke-test.sh --domain "$SPOKE_DOMAIN" --password "$KC_PASS"
```

**What it does:**
1. Gets a JWT from Keycloak
2. Mints an API key for `facebook-opt-125m`
3. Runs a completions inference request
4. Tests rate limiting with rapid requests
5. Cleans up the API key

## 5. Register Cross-Site Model Keys (manual)

Cross-site model access requires minting API keys on each site and distributing them via Policy 08. This step requires human judgment about which models to expose cross-site.

```bash
# On the hub: get a JWT and mint a key for site-b to use
JWT=$(curl -sk "https://keycloak.${HUB_DOMAIN}/realms/saas/protocol/openid-connect/token" \
  -d "grant_type=password" -d "client_id=tenant-demo" \
  -d "username=novatech-free" -d "password=${KC_PASS}" -d "scope=openid" | jq -r .access_token)

API_KEY=$(curl -sk "https://maas.${HUB_DOMAIN}/api/v1/api_keys" \
  -H "Authorization: Bearer $JWT" \
  -H "Content-Type: application/json" \
  -d '{"name":"site-b-cross-cluster","model_ids":["facebook-opt-125m"]}' | jq -r .api_key)

# Create the secret on the hub for Policy 08 to distribute
oc -n osac-platform create secret generic osac-cross-site-api-keys \
  --from-literal=site-b-api-key="$API_KEY" \
  --dry-run=client -o yaml | oc apply -f -
```

## 6. Adding a New Site

1. Add site-params keys in `hub/platform-sites/site-params.yaml`:
   ```yaml
   site-c.rhoai-channel: "stable-3.6"
   site-c.rhoai-source: "rhoai-catalog-dev"
   site-c.rhoai-fbc-image: "quay.io/rhoai/rhoai-fbc-fragment:rhoai-3.6@sha256:..."
   site-c.cluster-domain: "apps.site-c.example.com"
   site-c.identity-issuer: "https://keycloak.apps.hub.kni.syseng.devcluster.openshift.com/realms/saas"
   site-c.grid-enabled: "true"
   site-c.grid-site-name: "site-c"
   site-c.grid-network-name: "grid"
   site-c.grid-gateway-name: "grid-gateway"
   site-c.grid-namespace: "redhat-ai-grid"
   site-c.hardware-profiles: |
     [{"name": "cpu-only", ...}]
   ```

2. Create model and governance directories:
   ```
   global/sites/site-c/models/         (copy from site-a)
   global/sites/site-c/models.app.json (set site: "site-c", argoDestination: "site-c")
   global/sites/site-c/grid-models/    (copy from site-a)
   global/sites/site-c/grid-models.app.json
   tenants/novatech/sites/site-c/governance/
   tenants/novatech/sites/site-c/governance.app.json
   ```

3. Commit and push.

4. Import the spoke:
   ```bash
   ./scripts/import-managed-cluster.sh \
     --hub-context "$HUB_CTX" \
     --spoke-context "$SITE_C_CTX" \
     --cluster-name site-c \
     --yes
   ```

5. Add a declared peer in Policy 12 if needed for Grid cross-site routing.
6. Create a SiteInvite in Policy 12 for the new site (the enrollment protocol issues its identity cert automatically).

## 7. Troubleshooting

### Policy stuck NonCompliant

```bash
oc -n osac-platform describe policy <name>
oc -n <managed-cluster> get configurationpolicies -o wide
```

Look at the `complianceState` and `message` on each ConfigurationPolicy status.

### Argo Application not syncing

```bash
oc -n openshift-gitops describe application <name>
oc -n openshift-gitops logs deployment/openshift-gitops-argocd-application-controller | grep <name>
```

### Keycloak not starting

```bash
oc -n maas-db get pods -l app.kubernetes.io/name=keycloak
oc -n maas-db logs deployment/keycloak -c render-realm-import
oc -n maas-db logs deployment/keycloak -c keycloak
```

Common issues:
- CNPG cluster not ready yet → check `oc -n maas-db get cluster maas-db`
- ESO secrets not created → check `oc -n maas-db get externalsecrets`
- Signing keys not ready → check `oc -n maas-db get certificates`

### CNPG database issues

```bash
oc -n maas-db get cluster maas-db -o jsonpath='{.status.phase}'
oc -n maas-db get pods -l cnpg.io/cluster=maas-db
```

### ApplicationSet not creating Applications

```bash
oc -n openshift-gitops get applicationset osac-layers -o jsonpath='{.status.conditions}' | jq .
```

Common causes:
- Destination cluster not registered in ArgoCD — check `oc -n openshift-gitops get secrets -l argocd.argoproj.io/secret-type=cluster`
- Non-Kubernetes JSON files in manifest directories (e.g., Keycloak realm exports) — the ApplicationSet uses `include: '*.yaml'` to filter these out

### MultiClusterHub creation fails

The ACM operator webhook may not be ready when the CRD first appears. The bootstrap script retries automatically. If creating manually:

```bash
until oc apply -f multiclusterhub.yaml 2>/dev/null; do sleep 15; done
```

### Spoke not joining ACM

Check that both the CRDs and import manifests were applied to the spoke:

```bash
oc --context "$SPOKE_CTX" -n open-cluster-management-agent get pods
oc --context "$SPOKE_CTX" get klusterlet
```

### ArgoCD cluster secret missing for spoke

Verify the spoke is in the `global` ManagedClusterSet and `application-manager` addon is enabled:

```bash
oc get managedcluster <name> -o jsonpath='{.metadata.labels.cluster\.open-cluster-management\.io/clusterset}'
oc -n <name> get managedclusteraddon application-manager
```

### FBC catalog not resolving

```bash
oc get catalogsource rhoai-catalog-dev -n openshift-marketplace -o yaml
oc get imagedigestmirrorset quay-registry -o yaml
```

Verify the pull secret is in place:
```bash
oc -n openshift-marketplace get secret rhoai-catalog-pull-secret
```

### Grid enrollment issues

```bash
oc -n redhat-ai-grid get gridnetwork
oc -n redhat-ai-grid get gridsites
oc -n redhat-ai-grid get inferenceproviders
```

## Appendix A: Manual Bootstrap

For environments where scripts cannot run, the individual steps are:

1. `oc apply -f bootstrap/` — install GitOps operator
2. Wait for `applications.argoproj.io` CRD and `openshift-gitops` namespace + ArgoCD instance
3. Create `osac-platform` namespace
4. Create cluster-admin ClusterRoleBinding for Argo controller
5. Create ACM policy ClusterRole + ClusterRoleBinding
6. Patch Argo controller memory: `oc -n openshift-gitops patch argocd ...`
7. `oc apply -f hub/projects/` — AppProjects
8. Install ACM operator: namespace, OperatorGroup, Subscription (`release-2.17`)
9. Wait for MultiClusterHub CRD, then create MultiClusterHub (retry until webhook ready)
10. Create ManagedClusterSetBinding, GitOpsCluster, Placement in `openshift-gitops`
11. Create Git repo secret with `argocd.argoproj.io/secret-type: repository` label
12. Deploy `osac-layers` ApplicationSet (use `hub/applicationsets/` as reference, substitute `REPO_URL` and `GIT_BRANCH`)
13. Create `maas-db` namespace, hub-only Placement, and hub-templating RBAC in `osac-platform`
14. Seed Quay pull secret in `osac-platform` (if using FBC nightly)

See `scripts/bootstrap.sh` for the exact commands.
